# ADR-0001 · Legacy reuse and provenance

**Status** [PROPOSAL] Pending review · **Date** 18 November 2026 WIB

[Parent RFC](../rfc/RFC-0001-MERAJUT-RECONSTRUCTION.md)

## Decision

Clean rebuild on a fresh repo or explicit new history. Keep the immutable S4 ZIP off the public surface. Use legacy behavior as a domain reference. Require approval and lineage for any reused item, including original path and baseline hash, rights, changes and tests. Preserve historical documentation privately. S3 PDF p. 14 records the prior competition provenance.

## Alternatives

Incremental refactor would carry the old order model and exposure into the release. A clean-room stack change costs familiarity without resolving rights or originality.

## Consequences and verification

No automatic API compatibility or imported assets. Record attribution and license inventory, secret scan, dependency assessment and documented prior-work disclosure before any publication.

## Owners and open decisions

Engineering and provenance leads · Confirm reuse rights, desired history and any audited candidate.
